# 缄默之秋配置小助手

> **关于第三方中转站掺水路由、模型冒充与提示词篡改：请先看下面两张截图，再决定自己要不要继续买单。**

## 给因为请求被截断而来到这里的小朋友

你们好啊。既然都能顺着截断提示找到 GitHub，至少说明你愿意看一眼源码。那也请看看：有些中转站贩子卖的是模型名，实际给你的却未必是那个模型。**真正值得警惕的不是“中转”两个字，而是背着用户偷换模型、暗改请求，还继续装作原装服务。**

### 截图一：模型重定向

![模型重定向配置截图](docs/screenshots/model-redirection-example.jpg)

截图里展示的规则把 `gemini-3.1-pro-preview` 映射到 `gemini-2.5-pro`。这种机制本身可以用于公开、经用户同意的兼容处理；**如果拿它偷偷用其他模型冒充用户付费购买的模型，就是掺水造假。** 用户可能按更贵的型号付钱，得到的却是另一套能力、上下文表现和输出质量，还以为问题出在自己设置上。

### 截图二：额外系统提示词注入

![系统提示词注入代码截图](docs/screenshots/system-prompt-injection-example.jpg)

截图中的示例代码会在特定模型请求前插入 `system` 消息，要求模型自称另一种身份、报出指定知识截止日期，并隐瞒附加指令。**这不只是改个显示名称，而是在干预你实际收到的回答。** 它会破坏模型身份与输出的可信度，让用户难以判断回答受到了什么额外控制。

### 为什么这种做法伤害用户？

- **钱可能花得不明不白：** 标称高规格模型，实际被替换成其他模型，价格与交付不一致。
- **质量和判断被误导：** 你以为测的是某个模型的表现，结果测到的是路由商改造过的结果，排查问题、对比模型都失去依据。
- **回答可能被暗中引导：** 私自插入系统提示词可以改变身份声明、行为规则或输出内容，而用户无法从前端设置看出来。
- **信任和隐私风险上升：** 经由第三方转发的请求本就需要审视其日志、密钥和对话数据处理方式；再叠加不透明的改写，风险只会更难评估。

**都已经翻到 GitHub 了，就别只盯着模型名字和低价。** 先看服务商是否公开路由策略、是否允许核验实际调用模型、是否明确告知请求改写与数据处理方式。正常、透明、经用户同意的中转不该被一概否定；但偷偷掺水、冒充模型、隐瞒提示词注入的做法，不值得信任。

**关于截断名单：** 小助手的截断逻辑并非随意拦截，而是依据维护者收集的多方反馈与交叉核对整理，重点收录在相关用户群体中被反复指出存在模型偷换、路由掺水、提示词篡改等问题的中转站地址、关键词及其惯用名。
